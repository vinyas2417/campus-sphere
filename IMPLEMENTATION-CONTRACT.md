# Namma Sphere implementation contract

Java 21 source, Maven, JavaFX 21, SQLite and MySQL JDBC, JUnit 5. Package `com.campussphere`.

Shared public API (coordinate before changing):

- `model.Role` enum ADMIN, FACULTY, STUDENT.
- `model.User` record `(long id, String username, String name, Role role)`.
- `model.Row` record `(long id, Map<String,Object> values)`, methods `text(String)`, `number(String)` returning long, `decimal(String)`, `get(String)`. `text("id")` and `number("id")` return the id. Immutable defensive copy.
- `model.FieldSpec` record `(String key, String label, String type, boolean required, String reference, List<String> choices)`. Types text, email, password, integer, decimal, date, datetime, textarea, choice, reference. Empty reference/choices when unused.
- `model.ModuleSpec` record `(String key, String title, String singular, String group, List<FieldSpec> fields, Set<Role> readers, Set<Role> writers)`.
- `config.DatabaseConfig` record `(String url, String username, String password)` with static `fromEnvironment()`; default SQLite `data/campussphere.db`, environment CAMPUS_DB_URL, CAMPUS_DB_USER, CAMPUS_DB_PASSWORD.
- `database.Database(DatabaseConfig)`: `initialize()`, `Connection open()`, `boolean isMysql()`; schema initialization from classpath SQL resources.
- `repository.JdbcRepository(Database)`: `List<Row> findAll(String table)`, `Optional<Row> findById(String table,long id)`, `Row insert(String table,Map<String,Object>)`, `Row update(String table,long id,Map<String,Object>)`, `void delete(String table,long id)`, `List<Row> query(String sql,Object... params)`, `int execute(String sql,Object... params)`, `Database database()`. Whitelist tables/columns, prepared statements. Workflows may use JDBC connection directly in repository package helper; services must delegate raw SQL to repositories.
- `service.Session`: instance, `User requireUser()`, `Optional<User> user()`, `void signIn(User)`, `void clear()`.
- `service.AuthService(JdbcRepository,Session)`: `boolean needsSetup()`, `User setupAdmin(String name,String username,String email,String password)`, `User login(String username,String password)`, `void logout()`, `void changePassword(String oldPassword,String newPassword)`, `void createAccount(String name,String username,String email,String password,Role role,long profileId)` (admin only; profileId student/faculty id; ADMIN can be zero). Use BCrypt. No sample records or fixed credentials.
- `config.ModuleCatalog`: static `List<ModuleSpec> all()`, `ModuleSpec get(String key)`.
- `service.CampusService(JdbcRepository,Session)`: `List<ModuleSpec> modules()`, `List<Row> list(String key)`, `Row save(String key,Long id,Map<String,Object> values)`, `void delete(String key,long id)`, `List<Row> search(String key,String query)`, `Map<String,Long> dashboard()`, `List<Row> options(String key)`. Enforce service permissions, ownership and faculty course ownership. Manage foreign keys and validation. Restrict specialized tables to workflow-only writes to prevent bypass.
- `exception.CampusException` base unchecked exception with safe user message.
- `service.WorkflowService(JdbcRepository,Session)`: will provide booking, enrollment, attendance, approvals, library, registrations, reallocation, replies and notifications. Workflow agent must send signatures promptly to UI/root.

Core tables/columns (schema and catalog agent owns full definition, promptly tell workflow agent of changes):
users(id,username,email,password_hash,name,role,created_at), students(id,user_id nullable,usn,name,department_id,semester,section,email,phone,dob,address,admission_year,status), faculty(id,user_id nullable,name,department_id,designation,email,phone,address,qualification,experience,specialization,joining_date), administrators(id,user_id,name), departments(id,name,code,hod_id nullable), courses(id,code,name,credits,department_id,semester,faculty_id,capacity), resources(id,name,type,building,floor,capacity,status), resource_bookings(id,resource_id,user_id,start_time,end_time,purpose,status), course_enrollments(id,course_id,student_id), events(id,title,description,location,start_time,end_time,capacity), event_registrations(id,event_id,student_id), leave_requests(id,requester_id,type,request_date,from_date,to_date,reason,status,approval_remarks), timetable(id,course_id,faculty_id,resource_id,day_of_week,start_time,end_time), faculty_substitutions(id,timetable_id,faculty_id,date,start_time,end_time), attendance(id,course_id,student_id,date,status), library_resources(id,title,author,category,url,total_copies), library_borrowings(id,library_resource_id,student_id,borrowed_date,due_date,returned_date nullable), assignments(id,course_id,title,description,due_date), study_materials(id,course_id,title,type,url), exam_schedule(id,course_id,title,date,start_time,end_time,resource_id), announcements(id,title,body,audience,created_at), notifications(id,user_id,title,body,created_at,is_read), helpdesk_tickets(id,user_id,subject,description,status,response), activity_logs(id,user_id,action,entity,entity_id,created_at).

All SQL schemas must also define the remaining tables named in the user prompt; the metadata catalog exposes appropriate working CRUD where safe. Dates ISO, datetimes ISO local `yyyy-MM-dd'T'HH:mm`; timetable start/end `HH:mm`, day_of_week 1..7. No fake seed data.

Agents own separate files. Root owns pom, launch scripts, all controller/ui/task/app classes and CSS. Foundation agent owns config/database/repository core and service AuthService, Session, CampusService and shared Row/User/spec records. Workflow agent owns WorkflowService and WorkflowRepository. OOP agent owns Person hierarchy, Resource hierarchy, Leave hierarchy, generic Repository interface and typed repositories (coordinate foundation), custom functional interfaces, and integration tests + academic docs. CampusException/Role owned foundation.
